# Wade's Eve SEO Agent

This is an isolated, backend-only Eve sidecar. It has no public user interface, CMS, or application database. Its persistent records are versioned Markdown/JSON under the repository's `content/` and `seo/` directories.

Use Node 24 or newer; the pinned Eve `0.29.4` package requires it. `npm run lint`, `npm run format:check`, `npm run typecheck`, `npm run test`, `npm run dry-run`, and `npm run build` are isolated sidecar commands. The format command covers the versioned foundation files and every changed source file must be added to it or formatted consistently before review. The dry run needs no cloud credentials and performs no Git, Vercel, or publishing mutation. `npm run runtime:preflight` intentionally fails closed unless a production sidecar has either Vercel OIDC or an AI Gateway credential.

`npm run build` first stages a read-only `repository-snapshot/` containing only the site inputs needed for an audit: `app/`, `content/`, `seo/`, the Next configuration, and `actions/` when that directory exists. It then bundles that generated snapshot directly into Eve Build Output. The snapshot has a commit and content-digest receipt, and never includes environment files, credentials, Git metadata, or public-site dependencies. In Vercel Services, this allows the independently built sidecar to inspect the exact deployed repository state without adding Eve code to the public site's bundle.

Deploy this directory as the `eve_seo_agent` service in the repository's single Vercel Services project once Services access is `LIVE_VERIFIED`. The target topology lives in [`docs/seo-agent/vercel.services.example.json`](../../docs/seo-agent/vercel.services.example.json): this service gets its own root, lockfile install, and build, then is exposed only through a top-level `/_internal/eve` rewrite plus a request-path transform; it must never replace the public `site` service. Until that owner proof exists, root [`vercel.json`](../../vercel.json) stays site-only so the public site can deploy. Eve emits its own Vercel Build Output, Workflow, and Cron metadata, so the configuration deliberately does not duplicate Cron, output-directory, or service-level max-duration settings. Services is not a secret-isolation boundary: prefer Vercel OIDC and Connect, never expose agent values through `NEXT_PUBLIC_`, and revert to separate projects if a connector cannot be constrained safely. See `../../docs/seo-agent/SIDECAR_ARCHITECTURE.md` and `../../docs/seo-agent/MANUAL_SETUP.md`.

Vercel Blob is an optional private, bounded archive for already Git-backed audit bundles. It is disabled by default and cannot run from an audit-only workflow. A production archive requires a matching, human-approved run ID and a committed Git manifest receipt. Blob never replaces Git as the source of truth, stores raw research or secrets, serves public URLs, or authorizes publication. See the Blob section in `../../docs/seo-agent/MANUAL_SETUP.md` before enabling it.

The sole native Eve schedule runs every Monday at 16:17 UTC and starts a durable task session through the runtime channel. It returns after session creation rather than performing a long agent run in the cron request. It selects `audit` by default. For one exact administrator-invoked draft-PR proof, the server-only `SEO_AGENT_NATIVE_SCHEDULE_JOB=proposal` value may select the guarded proposal job, but it still requires every publishing approval gate and must be restored to `audit` immediately afterward. The `/api/cron` route remains a protected external dispatcher: production requests require `Authorization: Bearer <CRON_SECRET>` and compare the value with a timing-safe check. Native Eve scheduling is platform-authenticated and does not depend on that shared secret. `/api/healthz` and `/api/readyz` expose only redacted mode/readiness state; no route provides a UI.

Dispatch modes are `observe`, `propose`, `dry-run`, `paused`, and `disabled`. This implementation keeps all modes audit-only, defaults development to `dry-run`, and defaults the mutation kill switch to enabled. A deterministic daily run ID and idempotency key, Eve continuation token, active-session lookup, and short-lived process lock prevent duplicate starts without a database. Git-backed manifests deny already-recorded completed run IDs when the workflow executes. Do not deploy or enable this backend service until a human has completed the setup runbook and approved the first read-only production audit. The Vercel Sandbox backend uses Eve's published runtime image and denies all network egress. The agent has no generic shell, filesystem-write, unrestricted fetch/search, or deployment tool.
